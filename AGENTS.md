# Shoof

This repository contains Shoof's generic reporting source. Do not add real tenant configuration, identifiers, private reports, credentials or customer data. Demo files and test fixtures must be wholly fictional and visibly labelled. Use the injected read contract and caller-driven sync interface; no marketing connector, source credential loader or active scheduler is provided. The protected runtime uses a single externally allowlisted owner with magic links and passkeys. SMTP delivery uses only explicitly approved private configuration. No public registration or password login. Authentication POST routes require same-origin CSRF protections. Keep its reporting HTTP interface read-only; local imports require explicit external inputs and must preserve the last good report on rejection. Test authentication and persistence only with synthetic data in temporary external directories. Never configure real SMTP credentials, send real authentication email or register/revoke a real passkey without the required owner authorization.

Run npm test, npm run check, npm run build and npm run privacy for code changes. Run browser QA for UI changes when a local browser tool is available. Private runtime inputs must remain outside the repository. Builds always use fictional demo data and refuse private input environment variables. Do not invent software ownership or add a license without the owner's decision.

Before the first push and every later push, run `npm run review:publication -- <publication-base>` after committing, then review every outgoing diff and the origin of each fixture value as described in `docs/RELEASE-REVIEW.md`. Counts copied from private observations remain private even after changing names, dates or labels. Invent values from test requirements independently of private evidence; keep that evidence outside Git. A scanner pass is not provenance approval.
